# Code review, 22 Oct 2026

Whole-app review at `027a3bd` (v124) by four independent reviewers: correctness, design/maintainability, touch and timer races, reliability/data safety. Line numbers refer to that commit.

Status: `[ ]` open, `[x]` fixed (add the commit).

## Data safety (fix first)

- [ ] **1. P1: the first backup after a reinstall can replace the full iCloud backup.** `app.js:1481` `shareBackup`. The "fewer reflections than last time" warning reads `lastBackupCount` from localStorage, which is wiped with the data it protects (reinstall, iOS eviction, new phone). The first backup then silently overwrites the old file of the same name.
  Fix: when this device has no `lastBackupAt` but has data, confirm before sharing and offer "Restore your earlier backup first". Count likes in the shrink check too (store `lastBackupLikes`).
- [ ] **3. P2: deleting the reflection being edited, then tapping Done, brings it back.** `app.js:730`. The delete handler does not clear `editing`, so `saveDraft` (`app.js:850`) calls `journal.update` on the deleted record.
  Fix: after `await journal.delete(c)`, `if (editing?.id === c.id) setEditing(null);`.
- [ ] **4. P2: tapping Edit on another reflection discards the edit in progress.** `app.js:822` only saves a new draft before switching, not an edit.
  Fix: if `editing` and the text changed, `journal.update(editing, text)` before `setEditing(comment)`.
- [ ] **5. P2: a half-written reflection is lost if iOS kills the app in the background.** `app.js:861`. The text is saved only when the sheet closes.
  Fix: on `visibilitychange` to hidden (and `pagehide`) while the sheet is open, call `saveDraft()`.

## Touch and haptics

- [ ] **2. P1: the slide-off guard exists in four drifted copies.** Jump sheet `app.js:1040-1094`, History `477-515`, verse actions `535-573`, Reflections controls `1245-1274`. The two fixes from `91e06ad` (keep switches off after `touchcancel` until the next touch; the re-enable timer only acts for its own touch) exist only in History and verse actions. Reflections controls also don't swallow the click.
  Fix: one shared guard (refactor plan, phase 5).
- [ ] **6. P2: stale re-enable timer on the Reflections controls.** `app.js:1270`. A 400ms timer from the previous touch turns the switches back on in the middle of a new drag. Covered by finding 2.
- [ ] **8. P2: several sections write `.haptic.disabled`.** `app.js:1255`. The guard calls `setBackupEnabled` to restore what it overwrote; a backup finishing mid-drag can re-enable a switch. Fix: derive each switch from one rule (`button.disabled || inside .dragged`).
- [ ] **12. P3: the Jump sheet never clears `touch`.** `app.js:1090`. Later mouse or keyboard clicks can be swallowed.
- [ ] Lower confidence: a second finger's `touchstart` resets every guard, so the first (dragged) finger's release can still press. Guard on `Touch.identifier`.

## Lower-confidence risks

- [ ] `backedUp()` runs when the share sheet resolves, whatever target was chosen, so the reminder can go quiet without a file reaching iCloud.
- [ ] Safari-tab use (not Home Screen) risks iOS's 7-day storage eviction with no warning; `navigator.storage.persist()` result is not checked.
- [ ] `journal.js:20` has no `onblocked` / `onversionchange` handling for future database upgrades.
- [ ] `sw.js:54` can store a newer file into an older version's cache on a cache miss.
- [ ] If `prepareBackup` fails, the backup buttons stay disabled until the data changes.
- [ ] `shareBackup` has no in-flight guard; a double tap raises an `InvalidStateError` alert.
- [ ] If IndexedDB fails to open, `start()` rejects and reading the Bible is blocked too.
- [ ] The History menu is a `<div>`, not a `<dialog>`, so `anySheetOpen()` doesn't see it and auto-advance can run while it is open.
